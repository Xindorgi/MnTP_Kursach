# Введение

## Актуальность

Современный интернет невозможно представить без сервисов сокращения ссылок. Такие платформы, как Bitly, TinyURL и Short.io, ежедневно обрабатывают миллионы переходов, предоставляя пользователям возможность превращать длинные и нечитаемые URL в компактные короткие коды. Помимо очевидного удобства, эти сервисы выполняют важную функцию сбора аналитики: количество переходов, география пользователей, источники трафика, временная разбивка — эти данные критически важны для маркетинговых кампаний, мониторинга распространения контента и оценки эффективности рекламных каналов.

Однако существующие коммерческие решения имеют ряд ограничений. Во-первых, большинство из них являются проприетарными и предоставляют доступ к функциональности через API с жёсткими лимитами на бесплатных тарифах. Во-вторых, передача данных о переходах (включая IP-адреса и User-Agent) стороннему сервису поднимает вопросы конфиденциальности и соответствия требованиям законодательства (GDPR, 152-ФЗ). В-третьих, закрытый исходный код не позволяет адаптировать алгоритмы аналитики или генерации кодов под специфические нужды организации.

Таким образом, существует научно-практическая проблема: необходимость разработки собственного высокопроизводительного сервиса сокращения ссылок с открытой архитектурой, встроенной аналитикой переходов, определением геолокации по IP-адресу и возможностью развёртывания на собственной инфраструктуре.

**Объект исследования** — процесс сокращения URL-ссылок и сбора аналитики переходов в веб-приложениях.

**Предмет исследования** — алгоритмы и программные реализации сервиса сокращения ссылок на языке Go, включая механизмы кэширования, асинхронной обработки событий, геолокационного обогащения данных и batch-вставки в реляционную базу данных.

## Цель работы

Цель курсовой работы — разработать высокопроизводительный сервис сокращения ссылок с аналитикой на языке Go, реализующий REST API для создания и разрешения коротких URL, асинхронный сбор статистики переходов с GeoIP-обогащением, кэширование через Redis с in-memory fallback, и контейнеризацию для простоты развёртывания.

## Задачи

Для достижения поставленной цели необходимо решить следующие задачи:

1. Провести анализ существующих сервисов сокращения ссылок и методов сбора аналитики переходов, выявить их сильные и слабые стороны.
2. Спроектировать архитектуру сервиса, включая луковую модель слоёв (handlers → service → repository), схему базы данных, маршруты API и механизмы отказоустойчивости (in-memory fallback, graceful shutdown).
3. Обосновать выбор технологического стека: язык Go, веб-фреймворк Fiber v2, СУБД PostgreSQL 16, кэш Redis 7, библиотека GeoIP2 для геолокации, Sqids для генерации коротких кодов.
4. Реализовать ключевые компоненты сервиса:
   - REST API для создания коротких ссылок (`POST /api/v1/shorten`), редиректа (`GET /:code`) и получения аналитики (`GET /api/v1/analytics/:code`);
   - слой бизнес-логики с валидацией URL, генерацией коротких кодов через Sqids и управлением management-токенами;
   - репозитории для PostgreSQL и Redis с автоматическим переключением на in-memory реализации при недоступности внешних зависимостей;
   - асинхронный Analytics Worker, обрабатывающий click-события через буферизированный канал с GeoIP-обогащением и batch-вставкой в БД;
   - HTML-дашборд для визуального тестирования API.
5. Реализовать автоматические миграции базы данных, запускаемые при старте приложения.
6. Настроить контейнеризацию через Docker (многостадийная сборка с distroless-образом) и Docker Compose (PostgreSQL + Redis + приложение).
7. Обеспечить качество кода через статический анализ (golangci-lint), сканирование безопасности (gosec) и проверку уязвимостей зависимостей (govulncheck).
8. Провести модульное, интеграционное и E2E-тестирование сервиса, выполнить бенчмарки ключевых операций и оценить производительность.

## Практическая значимость

Разработанный сервис может быть использован как основа для создания корпоративного решения по сокращению ссылок с полным контролем над данными и инфраструктурой. Открытая архитектура позволяет легко расширять функциональность: добавлять новые источники аналитики, подключать системы мониторинга (Prometheus), интегрировать с внешними сервисами через webhook'и. Механизмы отказоустойчивости (in-memory fallback, асинхронная обработка, graceful shutdown) делают сервис пригодным для использования в production-среде. Результаты работы могут быть применены в учебных целях для изучения архитектуры веб-сервисов на Go, паттернов конкурентного программирования и принципов Clean Architecture.
